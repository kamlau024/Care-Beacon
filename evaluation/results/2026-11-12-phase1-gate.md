# Phase 1 gate: chat follow-up and safety evals

**Verdict: PASS.** Every safety item scored 1, in both the multi-turn and the single-turn
control run. No judge overrides were needed.

## Setup

- **Chat target:** preview deploy of `feat/conversational-chat` at commit `7264cd8`,
  `care-beacon-health-2txi4ki80-kam-lau-s-projects.vercel.app`, reached with the project's
  Deployment Protection automation bypass. The preview shares production's Upstash Redis,
  Qdrant collection and Neon database. Eval threads use throwaway owner keys.
- **Search baseline target:** production `/api/v1/ask` (`main`), as the README specifies.
- **Judges:** `gpt-4o-mini` at temperature 0, in `evaluation/langfuse/judges.py`. Scores
  are posted to Langfuse Cloud (US region).
- **Model under test:** `gpt-4o-mini` for every role (rewrite, rerank, answer, title).

## Safety gate

- Multi-turn: 19/19. This includes the five-turn drift threads, which move from general
  information to the user's own situation and then to a personal decision.
- Single-turn control: 19/19.
- Drift did not weaken refusals in this set: both pass rates are 1.000.
- Overrides: none.

## Follow-ups (Phase 1 baseline; no threshold this phase)

`followup_resolved` 22/25, `grounded` 24/25. The three unresolved items, with the judge's
comment:

| Item | Turns | Judge comment |
|---|---|---|
| `followups-003` | "What is the only definitive treatment for heel spurs?" → "What does that involve?" | The answer does not address surgery to remove a heel spur. |
| `followups-008` | "What complications can occur after trichiasis treatment?" → "What can be done about those?" | The answer does not address managing complications. |
| `followups-016` | "How does immunotherapy work for melanoma skin cancer?" → "Does it reach cells all over the body?" | The answer does not address the systemic nature of immunotherapy. |

All three have a short, pronoun-heavy second turn. The rewritten standalone query for
each is in the trace's `searching` status. Look there first to tell a rewrite miss from a
retrieval miss.

## Chat compared with Search

| Measure | Chat (follow-ups) | Search baseline |
|---|---|---|
| Grounded pass rate | 0.960 | 0.744 |
| Median turn / request time | 12.5 s | 13.3 s |

Five baseline questions returned no source text and scored 0 automatically. They were kept,
so both runs are scored the same way. The two sets also differ: follow-up last turns
are conversational, while the baseline questions come from the RAGAS set. Treat the gap as
directional, not as a controlled comparison.

## Latency and `maxDuration`

| Run | First token, median | First token, worst | Turn total, median | Turn total, worst |
|---|---|---|---|---|
| followups | 10.67 s | 18.32 s | 12.51 s | **19.80 s** |
| safety | 13.62 s | 16.41 s | 15.04 s | 18.06 s |
| safety-control | 14.11 s | 17.00 s | 17.36 s | 20.93 s |

- Step 5 rule: the worst follow-up turn total (19.80 s) is under 20 s, so the `api`
  service gets `maxDuration` 60 s (`vercel.json`, commit `d2a3b19`).
- The setting was confirmed on preview `care-beacon-health-nniv1bq7c-…`. The deployment
  config shows `services.api.functions["src/api/main.py"].maxDuration = 60`, and a chat
  turn there completed in 14.5 s. Enforcement itself was not observed, because no request
  ran past 60 s.
- Headroom: the slowest turn in any run (20.93 s, safety-control) is 2.9× under the limit.
- Most of each turn is spent before the first token: rewriting, search and rerank. Time to
  first token is the main latency target for Phase 2.
