# MCP server: Stage 1 acceptance smoke test

**Verdict: PASS, with one deviation to decide on.** Claude Desktop picked the tool for the 4 questions that ask for Care Beacon. The personal-advice question (5) was answered by Claude **without calling the tool**. The referral was kept, but the "tool is picked" criterion isn't met for that question. Everything else passed. Plan criteria: `docs/superpowers/plans/2026-11-16-mcp-server-plan.md`, "Stage 1 acceptance".

## Setup

- **Target:** preview of `feat/mcp-server` at `b16e41c` (deployment `care-beacon-health-o167uxhs2`), aliased to `care-beacon-mcp-preview.vercel.app`. CI was green on that commit. Previews share production's Redis, Qdrant and Neon.
- **Auth:** OAuth through Descope MCP Auth, with Claude's CIMD identity and the `ask` scope. Deployment Protection for Preview was paused for the Claude Desktop half and switched back on afterwards.
- **Two halves:**
  1. **Server side:** each question through the MCP tool (static `smoke` key) and through `POST /api/v1/ask` with the Search page's request body (`question`, `source` when restricted, `min_similarity`, default 0.5).
  2. **Claude Desktop:** the same 5 questions, typed by the user, with the URL-only OAuth connector.
- No production chat messages were sent.

## The deviation: question 5

Claude chose not to call Care Beacon for an urgent, personal question it could answer safely itself. Its reply kept the referral, so nothing unsafe happened. But the plan's criterion says the tool is picked for all five. Options:

- **Accept it (recommended):** for an urgent symptom, Claude referring straight away is the right result, and Care Beacon's own answer refers as well. Record the criterion as "picked when the question is in scope; for urgent personal questions, the referral must be kept".
- **Nudge tool choice:** add to the tool description that it should be used for treatment-side-effect questions even when they're personal, then retest. This risks Claude calling a medical-information tool for questions that need a clinician first.

## Notes

- The Desktop run was served from the answer cache, because the server-side run had just asked the same questions with the same settings. Capped MCP answers have their own cache key, separate from Search's.
- **OAuth on previews needs Deployment Protection paused.** Claude fetches `/.well-known/oauth-protected-resource…` and calls `/api/mcp` without the bypass. With protection on, the sign-in can finish while every later call gets Vercel's 401 ("Authorization … failed"). Production has no Deployment Protection.
- Descope stores the consent: removing the connector in Claude doesn't revoke it. To see the consent screen again, delete the consent in Descope.
